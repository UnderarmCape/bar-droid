**Claude:**

> I found the cause of the frame-end wait. A fix is on your phone, but it's untested; I need you in a game to check it.
>
> **Cause** (in the phone's graphics driver, lfdevs Mesa):
> - The driver has two ways to hand a finished frame to the screen. In the efficient one, a helper thread waits for the graphics chip and the game keeps working. In the fallback, the game itself stops until the frame is fully drawn. That stop is the 42–51% wait we measured.
> - The driver only uses the efficient way when it thinks the phone's kernel can't track frame completion on its own. Your Fold7's newer kernel says it can, but Qualcomm's graphics driver never feeds it that information. So every frame took the fallback and stalled.
> - Your game had no helper thread, which confirms this.
>
> **Fix:** our small library that already caps the frame rate now answers "not supported" to that one kernel query. The driver then switches to the efficient way. The X server part it needs is already in our build. If it misbehaves, a single setting (`BARDROID_PRESENT_FENCE=0`) turns it off.
>
> **What it should change:** the processor and graphics chip can work at the same time instead of taking turns. The graphics chip should also look busier, so Android may raise its clock. The same scene should run noticeably faster, top-down and tilted.
>
> **Risk:** the efficient way has never run on your phone before. If you see flicker, black frames or a freeze, tell me. Otherwise, once a busy game is on screen I'll check that the helper thread exists and the game has stopped waiting.
