### 16:44 · BAR Android port

**Kailil:**

> wait so this isnt a port? its running a translation or something? not a full port

**Claude:**

> It's in between. Nothing is translated, but it isn't a native port either: the phone runs BAR's official Linux engine, inside a small Linux environment the app carries.
>
> **What's native:**
> - The engine is BAR's own Linux arm64 build. Its code runs directly on the phone's CPU at full speed. There is no x86 emulation of the kind Winlator or Box64 use.
> - The graphics driver (Mesa's Freedreno) is an open-source driver for the Adreno GPU, so the phone's GPU draws the game's OpenGL directly.
> - The game's Lua and BAR's content are exactly what the PC runs.
>
> **What's the "wrapper":** the engine expects a Linux desktop, not Android, so the app provides one.
> - **A Debian Linux userland (proot):** gives the engine the Linux files and libraries it expects. proot works by intercepting some of the engine's system calls, which is the main cost of this approach. Narrowing which calls it intercepts took the phone from 14 to 30 fps.
> - **An X server inside the app:** gives the engine a desktop "window", which the app then shows on screen.
> - **Audio:** passed from the engine's Linux audio output to Android's.
>
> **Why not a full port:** a full port would rebuild the engine as a real Android app, with no container, no X server and Android's own graphics APIs. That needs engine changes, and online play needs BAR's official engine so every player's game stays in sync. Keeping the official binary is what makes online work today. A full port is what BAR's devs could do, and HELP-WANTED.md already names it as the next step ("an Android-native engine build (no proot, no X server)").
>
> **What it means for speed:** the biggest late-game cost is the engine's own simulation, and that already runs natively. A full port would remove the proot and X server overhead, but how much that gains has never been measured.
>
> Your Discord draft already describes it accurately ("official, unmodified Linux arm64 engine in a Debian container"). It doesn't use the word "port", but people will ask. Want me to add a line saying plainly that it isn't a native port yet?
