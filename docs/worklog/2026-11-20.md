**Claude:**

> The second independent review found a real security hole, and it's now fixed.
>
> **The hole:** any device holding the family key, including one removed from the family, could plant a file that runs automatically when you sign in to Windows. It worked by sending a file aimed at your user folder with a subfolder path that reached the Windows Startup folder. The new folder feature I added this morning (W43) opened that route. An older version of the same gap went back further: another device could already pick almost any folder in your profile, such as PowerShell's profile-script folder or the files at the top of your user folder.
>
> **The fix (commit c2074f5, W44):**
> - **Allowed folders:** files from another device may now only go into your own folders (Downloads, Pictures, Videos, Documents, Music, Desktop and any extra folders you've added). Within those, PowerShell's profile folders and anything named Startup or Start Menu are refused.
> - **The folder check:** the subfolder a sender asks for is checked again in full, and hidden or system folders along the way are refused.
> - **Download marking:** every received file is now marked as coming from elsewhere, just like a browser download, so scripts and programs ask before they run.
> - **Shortcut files:** `.url`, `.lnk`, `.scf` and similar types arrive renamed with `.txt` added. Windows can otherwise leak your sign-in credentials over the network just by showing their icons.
> - **Smaller fixes from the review:**
>   - OneDrive folders are no longer mistaken for links, so they can be sent.
>   - A drive root such as `C:\` works as a target.
>   - Empty folders are no longer left behind when a file is refused.
>
> New self-test checks confirm the Startup route and the PowerShell folders are refused, and that a received file carries the download marking.
>
> **The rest of the review (commit 01e1cc0, W45):**
> - Each device now has its own retry timer, so one device being away no longer holds up files queued for another.
> - Sending a folder of thousands of files no longer slows to a crawl, freezes the window or Explorer, or makes a second right-click send fail.
> - A notice now says when only the first 5,000 files of a folder were taken.
> - The window shows at most 60 transfers, then "… and N more".
>
> The self-test can't reach the new per-device retry timing, since that only runs inside the live program. AIRDROP restarted cleanly on it.
>
> All 70 self-test checks pass. The release 36 checklist now includes one more review of these fixes before anything goes out. Next pass at 08:23.
